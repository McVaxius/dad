# dad — changelog

## 2026-06-20
- Build fix (drive migration): `CopyPluginArtifacts` in dad.csproj hardcoded the now-removed
  `D:\temp\dad` dev-output path, which broke every Debug/Release build with MSB3191
  ("Unable to create directory D:\temp\dad\dad"). Repointed the default to `C:\temp\dad\<AssemblyName>`
  and made it overridable: `<DadDevPluginOutput Condition="'$(DadDevPluginOutput)' == ''">`.
  Override with `dotnet build -c Debug -p:DadDevPluginOutput=<path>`. Debug build now succeeds (0 warnings, 0 errors).
  Backup of the original csproj saved under backups/.

## 2026-06-20 — Code review remediation (docs/octo-review-2026-06-20)
Phase 1 (bounded fixes) — build green, 14/14 tests pass:
- H7: OnFrameworkUpdate now isolates each per-frame service in its own try/catch (RunFrameworkStep)
  so one faulting service can no longer throw out of the Dalamud tick and freeze the plugin.
- L5: removed the duplicate `RequiresServerDadAuthority` from Plugin.cs; single source of truth is
  now `DadCoordinatorService.RequiresServerDadAuthority` (internal static).
- M9: `ResolvePlannerGroup` now delegates to the ambiguity-rejecting resolver (returns null on
  duplicate GroupId/DisplayName instead of an arbitrary list-order pick → no more wrong-roster starts).
- L1: `HandleWorkerExecutionCancel` now enforces the `remoteMutationsAllowed` gate like every other
  mutating transport handler.
- L3: removed the hardcoded `Z:\!ff14clientboot` const; boot directory is now `Configuration.ClientBootDirectory`
  (default preserved). `IsAllowedBootBatchPath` parameterized for testability.
- M15: renamed Services/DadDutySupportQueueService.cs → DadNpcDutyQueueService.cs to match its type.

Phase 2 (bounded correctness bugs) — build green, 14/14 tests pass:
- H2: `DadCoordinatorService.ResolveAuthorityEndpoint` now returns `GetPreferredAuthorityEndpoint()`
  (configured target first, discovered peer as fallback) so start/cancel match what the UI shows and
  no longer silently fail before peer discovery populates the endpoint.
- H3: `DadWorkerExecutionService.Cancel` now drains matching pending (accepted-but-not-started) commands
  via DrainPendingForRun, closing the ACK→Update race where a cancel was rejected and the command still ran.
- H4: Trust selection (`DadNpcDutyQueueService`) now null-guards the native member pointer before
  dereferencing candidate offsets (the realistic crash vector during zone/agent transitions).
- M7: `DadLocalDutyQueueService` captures the Duty Finder unrestricted/unsynced flag before overriding it
  and restores it on duty entry, cancel/clear, and next-run start (RestoreUnrestrictedParty) so an unsynced
  Dad run no longer leaks that setting into later manual/synced queues.
- Remaining in Phase 2 (deferred — behavior-sensitive, need in-game verification): M5 preview/runtime
  parity, M6 single global active executor, M8 territory entry-transition timeout.

Phase 3 (concurrency locks) — in progress, build green, 14/14 tests pass:
- C4: `DadClaimService` now guards every method with a single lock (activeLeasesBySlot /
  localAcceptedLeasesByCharacter), making check-then-act lease logic atomic and enumeration safe —
  fixes the double-claim / collection-modified race between the coordinator (framework thread) and the
  transport background thread.
- Remaining in Phase 3: M14 transport KnownParticipants/registry locking (sequenced into Phase 5).

Phase 4 (framework-thread marshaling — the #1 review fix) — build green, 14/14 tests pass:
- C1/C3/C5/H5 + H6(threading): `DadTransportService.HandleClientAsync` now runs the ENTIRE inbound
  handler dispatch on the Dalamud framework thread via `Plugin.Framework.RunOnFrameworkThread(DispatchEnvelope)`;
  the socket thread only does I/O and awaits the result. Coordinator run-state, presence, claim, and
  worker-execution state are now mutated on a single thread, eliminating the off-thread game-memory access
  and the collection-modified/torn-state races that crashed the client and corrupted runs.
  → C5 (presence) is resolved by this marshaling (no lock needed); C4's lock is retained as defense-in-depth.
  → Note: outbound sends triggered by these handlers are still synchronous; Phase 5 makes them async so the
    framework thread isn't blocked on remote start/cancel.

Transport hardening + CI (Phases 6/8 partial) — build green, 14/14 tests pass:
- C2(a): remote character-load no longer executes peer-supplied raw command strings unless the operator
  opts in via new `Configuration.AllowRemoteCommandExecution` (default false). Closes the headline
  remote-arbitrary-slash-command hole. (Full HMAC envelope auth = C2(b), tracked as follow-up.)
- M2: `DadIpcJson` JsonOptions MaxDepth=32; inbound transport line capped at 256 KB before deserialize.
- M3: peer-discovery registry moved from world-readable %TEMP% to the per-user plugin ConfigDirectory
  (still shared across this user's game instances for multibox discovery).
- L4: concurrent client handlers bounded by a SemaphoreSlim(32) with backpressure.
- M11: in-flight client handlers tracked and drained (bounded) on Dispose; CTS + semaphore disposed;
  per-connection TcpClient disposed.
- H8: CI workflow now runs `dotnet test Tests\dad.Tests.csproj` before publishing the release.
- M17: added `DadIpcContract.ApiVersion` (=1) + a `dad.ApiVersion` IPC gate (registered in DadIpcService)
  so consumers/peers can detect contract drift; documented the StartTasks/StartRun alias.

## 2026-06-21 — Remediation Phase 6 complete (C2(b) HMAC envelope auth)
- New `Configuration.TransportSharedSecret`. When set, `SendEnvelope` stamps every transport envelope with an
  HMAC-SHA256 over MessageType+PayloadJson, and inbound `HandleClientAsync` rejects any envelope whose HMAC
  doesn't match (constant-time `CryptographicOperations.FixedTimeEquals`). Empty secret = no auth (loopback
  default, backward-compatible). StartListener now logs a loud warning when bound to a non-loopback interface
  without a secret. Settings UI: shared-secret field in the Completion & Safety → Integrations section.
  Phase 6 complete (C2a + C2b + M1-partial + M2 + M3 + L4 + M11).
