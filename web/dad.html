Duty Planner Multibox Schedules

Overview

DAD turns repeatable duty work into reusable Plans. Choose the activity, crew, requested jobs, wake/relog behavior, loot rules, stop condition, and finish actions once, then review the same explicit contract before every run.

Five guided workflows cover Coordinator setup, Client setup, a first Plan, the crew, and a first Schedule. Existing launch-profile metadata is optional debug-only scaffolding; DAD does not execute its batch paths or start a missing game process.

Every live start uses the scheduler-backed path. DAD checks the Coordinator and every selected Client for Fren Rider, AI Duty Solver, vnavmesh, XA Database 0.0.0.39+, XA Slave, and either BossModReborn or BossMod before new work can mutate the crew or queue. A persistent dependency window explains anything missing, disabled, outdated, or still being checked.

Key Features

Guided Setup and Reusable Plans

Save activity rules and reusable crews, or follow guided workflows from first connection through first Schedule.

Coordinator and Client Readiness

See authenticated routing, reconnect state, worker roles, requested jobs, and exact-character preparation before queueing.

Prepared, Verified Parties

Coordinate takeover or relog for an already connected same-account client, prepare jobs, assemble the saved crew, and verify the party. A fully absent client must be started manually.

Scheduler-Backed Runs

Run one Plan now or chain ordered Plans and repeats into manual or daily-reset Schedules.

Plan and Schedule Sharing

Export versioned clipboard shares, preview ID-based replacement, then remap anonymous crew locally before validation.

Visible Safety and Recovery

Read the first blocker and live status, cancel scoped work, or use guarded Stop All to drain DAD-owned activity across the crew.
